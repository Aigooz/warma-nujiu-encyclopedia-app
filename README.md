# Warma / 怒九 百科 App

这是一个原生 Android 百科应用，不是网页套壳。应用使用 Android 原生布局重新组织 Warma 百科与怒九百科的数据，提供底部分栏、原生列表、卡片、筛选器、图表和答题界面。

## 主要功能

### 双站点切换

- Warma：包含主号「Warma」与小号「warma养鸽场」。
- 怒九：包含主号「怒九笑」与小号「怒九摸鱼馆」。
- 两个站点的解析结果会保留在内存中，首次启动后切换站点可以立即渲染缓存数据，后台再检查更新。
- 数据洞察拆分为「榜单 / 节奏 / 标签 / 深度」四个移动端分区，减少长页滚动压力。

### 原生页面

- **首页**：UP 档案、核心数据网格、年度弹幕趋势、内容分类、最新视频和弹幕梗。
- **视频**：搜索标题、标签、弹幕梗或 BV 号，支持账号、类型、年份、字幕行数与本地收藏筛选，以及时间、热度、互动率、字幕量排序。筛选条件联动首页和数据洞察，两个百科分别保存当前筛选。
- **详情页**：统计面板、弹幕时段曲线、可搜索标签、简介、弹幕峰值、收藏、系统分享和 B 站跳转。
- **榜单**：播放、点赞、弹幕、投币、收藏、评论、分享 Top 10。
- **数据洞察**：年度投稿与累计增长、发布时钟、星期更新节奏、荣誉里程碑、标签关键词云、标签关联 PMI、内容特征聚类、相似内容检索。
- **答题**：分类与难度筛选、10 题挑战、进度保存、正确率与加权积分、错题解析。重复作答不计分，重新开始需确认，切换百科会清除当前轮次。
- **设置**：站点切换、系统 / 浅色 / 深色主题、同步状态、数据刷新、检查 APP 更新、打开网页版。

切换底部分栏会保留页面状态。年度弹幕图使用全站年度数据，其余视频统计按当前筛选计算；本地收藏与 B 站账号收藏相互独立。

### 数据同步

APP 启动后会从两个 GitHub Pages 数据源拉取最新 `data.js` 与 `data-quiz.js`，并缓存到本地；首次启动或网络不可用时使用 APK 内置快照兜底。因此百科内容更新时通常不需要重新安装 APP。

## 下载

1. 打开本仓库的 [Releases](https://github.com/Aigooz/warma-nujiu-encyclopedia-app/releases)
2. 下载最新版的 `app-release.apk`
3. 安装到安卓设备

> 首次安装未知来源应用时，系统会提示授权，允许即可。

## 发布新版本

如果 APP 本身升级，只需要：

1. 修改 `app/build.gradle` 中的 `versionCode` 和 `versionName`
2. 提交并打 tag，例如 `v1.1.0`
3. GitHub Actions 会自动构建并发布新的 Release

APP 内提供“检查更新”入口：自动读取 GitHub Release，直接下载 APK，下载完成后唤起系统安装界面，不再需要先跳转浏览器。

更新下载默认使用 GitHub 官方线路，失败或连续 30 秒没有进展时按顺序尝试 `ghfast.top`、`gh-proxy.com` 两条第三方备用线路，也可以手动选择线路或使用浏览器下载。备用线路的可用性因网络而异。安装前校验文件大小、GitHub 提供的 SHA-256（如果存在）、包名、版本号与当前应用签名；校验失败的文件不会交给安装器。下载任务在切换页面、重建页面后恢复，未知来源安装权限可从应用内授权。

旧版的单源下载逻辑无法远程修复；若旧版无法下载，请先从 Release 或备用线路手动安装 1.3.1 或更新版本。

## 构建

GitHub Actions 会自动构建。需要本地构建时：

```powershell
gradle assembleRelease
```

验证筛选、排序、时长解析、答题计分及两套内置数据：

```powershell
gradle :app:testDebugUnitTest :app:lintDebug
```

Windows + JDK 17 在中文目录下若出现测试类 `ClassNotFoundException`，可使用系统代码页启动独立 Gradle 进程（仅影响该次构建，不修改源码编码）：

```powershell
gradle --no-daemon '-Dorg.gradle.jvmargs=-Xmx2048m -Dfile.encoding=GBK' :app:testDebugUnitTest
```

当前内置数据快照较大，属于有意设计：它用于保证第一次启动或离线状态下也能浏览完整百科。
